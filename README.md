# Moonlight

企业研发团队内部管理工具。核心逻辑用 Rust 实现，交互界面为内嵌的单页 Web 控制台，
编译产物是一个不依赖外部资源的独立二进制。

系统分工程管理与经济决策两层，派工与排期结论均可追溯到具体的成本、工期与净现值。

## 工程管理层

- **任务看板**：待办 / 进行中 / 待评审 / 已完成四列，拖拽卡片即可流转状态。
- **资源负载**：按跨学科折算后的实际投入统计负载率，超载与吃紧分级标色。
- **风险预警**：逾期、临期未开工、P0 未派工、成员过载、产能缺口、跨学科溢价、
  投入产出倒挂、人员闲置；适用的风险附成本或延期损失估算。
- **团队健康度**：未逾期比例 40% + 负载均衡 35%（负载率标准差）+ 派工覆盖 25%；
  任一成员过载时最高 74 分，超过 130% 时最高 59 分，避免全员一起过载仍获高分。

## 经济决策层

- **多学科成本模型**：学科距离决定工时膨胀系数（同学科 1.0，前后端互援 1.25，
  研发↔运维 1.35，测试↔研发 1.40，测试↔运维 1.50，产品↔技术 1.70），跨学科另计沟通对齐工时。
  团队缺失某个学科时，该学科的任务只能溢价承接，缺口代价会直接出现在账面上。
- **净现值 NPV**：业务收益按交付日贴现，逾期再扣延期损失，减去总投入。
- **边际成本递增与产能硬约束**：超出周产能按加班计价，进入疲劳区后追加溢价，
  超过可持续上限判定为不可行方案。
- **WSJF 排序**：延期成本 ÷ 任务规模，用于未派工任务的处理顺序；默认延期损失仍受 P0/P1/P2 影响。
- **决策矩阵**：单个任务列出全部候选方案的工时、成本、加班溢价、完成日、延期损失、
  产能占用、NPV、ROI、延期损失等值天数，并给出赶工溢价与延期代价的权衡结论。
- **投资组合**：团队周产能是预算，净现值是回报，按单位工时净现值贪心取舍，
  给出本周该做哪批任务、哪些顺延、哪些因投入产出倒挂应当砍掉。

## 计量口径

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| 人力成本 | 元/小时 | 全成本口径，含社保公积金与管理分摊 |
| 业务收益 | 元 | 季度可量化收益或成本节约 |
| 年化贴现率 | 12% | 管理假设，日率按 12% / 365 近似 |
| 延期日损失 | 收益 × 2% × 权重 | P0/P1/P2 对应 1.5/1/0.5，显式填 0 表示无损失 |
| 加班溢价 | 超产能部分 +50% | 疲劳区（>120%）部分再追加 150% |
| 可持续产能上限 | 130% | 超过即判定方案不可行 |
| 跨学科沟通成本 | 2 小时/任务 | 与工时膨胀系数叠加 |

以上数值是课程演示用的管理假设，并非历史数据拟合结果。参数定义于 `src/economics.rs`。
预计完成日按周产能 / 5 折算工作日、跳过周末；暂不包含法定节假日。收益在模型中简化为交付日一次实现，延期损失按自然日累计。
“损失等值天数”是总投入 / 延期日损失，不是现金流投资回收期。
自动派工只分配已估值且有正净现值可行方案的未完成任务；手动分配由用户判断。
投资组合是按单位工时净现值的贪心建议，不保证全局最优，不替代完整的依赖排程。
在手总览是对各任务在当前队列下的独立情景估算，不代表财务结算或逐任务排程后的现金流预算。

写请求先在副本中执行，JSON 落盘成功后才提交内存状态；失败返回 HTTP 500，保留原状态。
本工具未实现登录、权限与审计，仅适合可信本地演示；安全响应头不等于身份授权。

## 运行

```bash
cargo run --release
# 默认监听 http://127.0.0.1:8088，数据落在 data/moonlight.json
```

可选参数：

```bash
cargo run --release -- --port 9000 --data /path/to/team.json
```

首次启动若数据文件不存在，会自动写入一份演示数据：5 名成员覆盖 4 个学科
（缺运维），13 个任务中含 1 个逾期、2 个只能跨学科承接、1 个净现值为负，
在手需求约 156 小时而团队周产能 134 小时。

## 结构

| 文件 | 职责 |
| --- | --- |
| `src/model.rs` | 领域模型：成员、任务、学科、优先级、状态 |
| `src/store.rs` | 内存数据 + JSON 落盘 |
| `src/economics.rs` | 成本核算、NPV、ROI、WSJF、决策矩阵、投资组合 |
| `src/insight.rs` | 负载统计、一键派工、风险预警、团队健康度 |
| `src/http.rs` | 极简 HTTP/1.1 服务 |
| `src/api.rs` | 路由与参数校验 |
| `src/web/index.html` | 内嵌前端页面 |

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 成员、任务、负载、预警、健康度、经济总览全量快照 |
| POST | `/api/members` | 新增成员 |
| DELETE | `/api/members/{id}` | 移除成员，其名下任务退回未派工 |
| POST | `/api/tasks` | 新建任务 |
| PATCH | `/api/tasks/{id}` | 局部更新，`assignee: null` 表示取消派工 |
| DELETE | `/api/tasks/{id}` | 删除任务 |
| GET | `/api/tasks/{id}/decision` | 该任务的决策矩阵与推荐依据 |
| POST | `/api/auto-assign` | 按 WSJF 排序、净现值最优派工 |


## 报告验收与复现

报告的网页、统计图和验收日志使用隔离的默认演示数据，不覆盖 `data/moonlight.json`。

```bash
python3 scripts/verify_report.py
# 新数据文件须不存在；首次启动自动生成演示数据
cargo run --release -- --port 18089 --data /tmp/moonlight-report-demo.json
# 保存 GET /api/state 的派工前快照，再 POST /api/auto-assign，保存派工后快照
```

本次证据保存于 `docs/evidence/2026-09-05/`。日期会影响延期与净现值；跨日期重跑应以新的接口快照为准。
